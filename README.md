# copy-paste symbols

**1,275 copy-and-paste symbols in 23 categories — hearts, heart combos, stars, arrows,
brackets, math, currency and more — with category names in six languages and Unicode facts
for every code point.**

Browse and copy them at **[fontvibe.ai/tools/heart-symbol](https://fontvibe.ai/tools/heart-symbol)**
— one click to copy, no install. Music notes are at
[fontvibe.ai/tools/music-note-symbol](https://fontvibe.ai/tools/music-note-symbol), degree
signs at [fontvibe.ai/tools/degree-symbol](https://fontvibe.ai/tools/degree-symbol), and every
other category in the Symbols tab of the
[fancy text generator](https://fontvibe.ai/tools/fancy-font-generator).
This repo is the raw data behind those pages.

```text
1,275   symbols, deduplicated
  686   of them multi-character: heart combos, decorations, emoji sequences
  982   distinct code points, every one assigned in Unicode 16.0.0
   23   categories, each named in en · es · pt · de · ja · zh
  192   fully-qualified emoji (Emoji 16.0)
```

Prefer a package to a download?

```bash
npm i copy-paste-symbols        # or: npx copy-paste-symbols heart
pip install copy-paste-symbols
```

Kaomoji are not in here — they have their own dataset:
[fontvibe-kaomoji](https://github.com/Funovate-Technology/fontvibe-kaomoji).

## What's different

Ranked by how strong the evidence is. We separate what we measured from what we're guessing.

### 1. It's a symbol site's selection, not a Unicode dump

Unicode has well over a hundred thousand characters; a symbol site needs the few hundred
people actually copy, grouped the way they look for them. That curation — which characters,
which categories, in what order — is what this repo contains. Order inside each category is
the order fontvibe.ai shows them.

686 entries are more than one character: heart combos like `˚₊‧꒰ა❤︎໒꒱ ‧₊`, decorations,
and emoji sequences. Those don't exist in any Unicode table or emoji list, because they
were never characters in the first place.

### 2. Every code point checked against Unicode — measured

For each of the 982 distinct code points: official name, general category, block, the
Unicode version it was added in, and its Emoji / Emoji_Presentation properties. For each
whole entry: its status and CLDR short name in `emoji-test.txt`, if it is listed there.

Names and general categories come from Python's `unicodedata` at Unicode 16.0.0 (Python 3.14);
blocks, ages and emoji properties from the official Unicode 16.0.0 and Emoji 16.0 data files.
Nothing was typed in by hand, and [a script re-derives all of it](#verify-it-yourself).

That check caught 1 entry the site was serving that isn't a character at all: `U+03A2`, the
unassigned gap in the Greek block where a capital final sigma would go. It renders as a box
or as nothing. It's excluded here and listed in `stats.json` under `excluded`.

### 3. Category names in six languages — measured

Every category carries its label in en · es · pt · de · ja · zh — the same labels the
localized fontvibe.ai pages use. The packages resolve any of them, so
`byCategory('Corazones')` and `byCategory('ハート')` return the same hearts.

**What isn't localized:** per-symbol names. Those are the official English Unicode names
(`BLACK HEART SUIT`) and CLDR emoji names (`red heart`). We didn't translate them rather
than ship guesses.

### 4. `unicode_version` — **a hypothesis, not a finding**

Each entry carries the highest Unicode version among its code points: roughly, how new a
phone or font has to be to show it. We think that's useful for a copy-paste site
(hide what old devices will render as boxes), but we don't know that anyone wants it.
If you do or don't, [open an issue](https://github.com/Funovate-Technology/fontvibe-symbols/issues/new).

## Files

| File | Use it for |
|---|---|
| `data/symbols.json` | **Start here.** Every symbol, one record each |
| `data/by-category/*.json` | One file per category: the category's labels and page, then its symbols in site order |
| `data/symbols.csv` | Flat table with a header row; multi-valued cells are `\|`-joined |
| `data/categories.json` | Category keys, slugs, six-language labels, counts, fontvibe.ai page |
| `data/stats.json` | Counts, machine-readable, plus the excluded entries |

Field definitions: [SCHEMA.md](SCHEMA.md).

## Quick start

```python
import json
syms = json.load(open("data/symbols.json", encoding="utf-8"))

hearts  = [s["text"] for s in syms if "Hearts" in s["categories"]]
old_ok  = [s for s in syms if tuple(map(int, s["unicode_version"].split("."))) <= (6, 0)]
singles = [s for s in syms if s["length"] == 1 and not any(s["emoji_presentation"])]
```

```js
import symbols from 'copy-paste-symbols'

symbols.byCategory('Arrows')            // in site order
symbols.byCategory('矢印')               // same thing — labels work in six languages
symbols.search('star', { limit: 5 })    // by Unicode / emoji name or category
symbols.get('U+2665')                   // → { text: '♥', unicode_names: ['BLACK HEART SUIT'], … }
```

## Verify it yourself

Every number on this page is checked by one stdlib-only script:

```bash
python scripts/verify.py              # downloads the Unicode 16.0 data files
python scripts/verify.py --offline    # skip the network checks
```

It re-derives every Unicode fact, cross-checks `symbols.json` against the per-category files,
the CSV and `stats.json`, confirms there are no duplicates and no unassigned code points,
checks that every linked fontvibe.ai page answers, and fails if this README states any number
it didn't verify — including every row of the category table above.

`scripts/build_dataset.py` rebuilds `data/` from the public API that fontvibe.ai itself uses.
